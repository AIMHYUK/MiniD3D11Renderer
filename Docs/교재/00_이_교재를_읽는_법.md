# 00. 이 교재를 읽는 법

> 상태: 진행중 · 갱신 2026-08-11 · 관련: [7일 커리큘럼](../7일_커리큘럼.md), [공부 로드맵](../공부_로드맵.md), [작업일지 목차](../_목차.md)
> 무엇: 이 교재가 무엇을 다루고 무엇을 안 다루는지, 어떤 순서로 읽고 각 장을 어떻게 소화할지.

---

## 이 교재가 목표하는 것

**7일 뒤에 이 질문들에 답할 수 있는 것.**

- 정점 하나가 화면 픽셀이 되기까지 무슨 일이 일어나는가
- 드로우 콜은 왜 비싼가. 줄이는 방법은 무엇인가
- 프레임이 느릴 때 CPU 탓인지 GPU 탓인지 어떻게 가르는가
- 투명한 물체는 왜 순서가 중요한가

전부 면접에서 실제로 나오는 질문이다.
API 함수 이름을 외우는 것은 목표가 아니다. **문서 보고 쓰면 된다.**

## 다루지 않는 것

3D 변환 행렬, 조명, 그림자, 뎁스 버퍼, 스켈레탈 애니메이션, 포스트 프로세싱.
7일에 넣을 수 없고, 이 프로젝트(2D 스프라이트 배칭 실험)에 필요하지도 않다.
필요해지면 그때 판다.

---

## 이미 아는 것에 붙이기

언리얼과 유니티를 6개 프로젝트에서 썼다. **그때 쓰던 것이 여기서는 무엇인지**를
장마다 대조표로 붙여 두었다. 새로 외우는 게 아니라 이름을 바꿔 다는 작업에 가깝다.

| 엔진에서 쓰던 것 | 이 교재에서 |
|---|---|
| Material | 셰이더 + 상태 객체 + 상수 버퍼 묶음 |
| Material Instance의 파라미터 | 상수 버퍼 (3장) |
| Texture 에셋 | 텍스처 + SRV + 샘플러 (4장) |
| Static Mesh의 정점 데이터 | 정점 버퍼 + 인덱스 버퍼 (2~3장) |
| Draw Call / Batches (통계 창) | 6장 전체 |
| Instanced Static Mesh | 인스턴싱 (7장) |
| `stat unit`, Profiler | 계측 (8장) |
| Blend Mode: Translucent | 블렌드 상태 (5장) |

**엔진은 이걸 전부 자동으로 해준다.** 그래서 편했고, 그래서 문제가 생겼을 때 안이 안 보였다.
한 번 손으로 하고 나면 엔진 안이 보이기 시작한다. 그게 이 교재의 진짜 목적이다.

## 각 장의 구조

모든 장이 같은 순서다.

```
1. 왜 필요한가      — 이게 없으면 무엇을 못 하는가
2. 개념             — 그림과 표
3. 코드로는          — 실제 D3D11 호출
4. 엔진에서는        — 언리얼/유니티의 무엇에 해당하는가
5. 흔한 함정         — 여기서 대부분 막힌다
6. 확인 문제         — 답할 수 있으면 넘어간다
```

**5번을 대충 읽지 말 것.** 하루를 날리는 지점이 거기 다 적혀 있다.

---

## 하루 리듬

```
개념 읽기 1시간  →  구현 2~3시간  →  작업일지 30분
```

**작업일지를 미루면 안 된다.** 7일 뒤 이 일곱 편이 그대로 제출 문서의 재료가 된다.
따로 쓰는 시간을 잡아두지 않았다.

작업일지에 넣을 넷:

1. 무엇을 했는가 — 스크린샷이나 숫자부터
2. 어떻게 했는가 — 코드 조각 + 왜 그 선택인지
3. **막힌 것** — 원인을 어떻게 좁혔는지까지. 면접에서 제일 많이 쓰인다
4. 참고한 것 — 링크 + 거기서 얻은 것

---

## 막혔을 때

**2시간 규칙.** 한 곳에서 2시간 넘게 막히면 넘어간다.
대신 **막힌 상태 그대로 작업일지에 남긴다** — 무엇을 시도했고 무엇을 예상했고 실제로 뭐가 나왔는지.

다음 날 다시 보면 대개 풀린다. 안 풀려도 그 기록이 남으면 손해가 아니다.
"이건 아직 못 풀었습니다. 여기까지 좁혔습니다"는 면접에서 나쁜 답이 아니다.
오히려 **아무 데서도 안 막혔다는 포트폴리오가 의심스럽다.**

## 디버깅 순서

그림이 안 나올 때 이 순서로 본다. 위에서부터 훑으면 대부분 여기서 잡힌다.

1. **출력 창을 본다** — Debug 빌드는 D3D 디버그 레이어가 켜져 있다.
   잘못 쓴 API가 문장으로 찍힌다. 이걸 안 보고 코드를 노려보는 게 제일 흔한 시간 낭비다.
2. **셰이더가 컴파일됐는가** — 오류 메시지 박스가 떴는지
3. **정점 순서가 시계 방향인가** — 반시계면 백페이스 컬링으로 사라진다
4. **좌표가 NDC 범위(-1~1) 안인가** — 100 같은 값을 넣으면 화면 밖이다
5. **셋이 맞는가** — C++ 구조체 ↔ 입력 레이아웃 ↔ HLSL 입력
6. **`OMSetRenderTargets`를 했는가** — 플립 모델은 매 프레임 다시 해야 한다
7. **알파가 0은 아닌가** — 블렌딩을 켠 뒤에 자주 겪는다

# 02. 좌표계 — NDC와 화면 픽셀

> 상태: 진행중 · 갱신 2026-08-11 · 관련: [교재 목차](00_이_교재를_읽는_법.md), [01. 그림이 화면에 나오기까지](01_그림이_화면에_나오기까지.md), [03. 상수 버퍼와 인덱스 버퍼](03_상수버퍼와_인덱스버퍼.md)
> 무엇: 정점 셰이더가 내놓아야 하는 좌표가 무엇인지, "화면 (100, 50)에 200×200 크기"를 어떻게 그 좌표로 바꾸는지.

---

## 1. 왜 필요한가

지금 삼각형 좌표가 셰이더에 사실상 박혀 있다.

```cpp
{  0.0f,  0.5f, ... },   // 이 0.5는 대체 무슨 단위인가?
```

스프라이트를 만들려면 **"화면 (100, 50) 위치에 200×200 픽셀 크기"**로 말할 수 있어야 한다.
그러려면 픽셀 단위와 GPU가 쓰는 단위 사이를 오갈 줄 알아야 한다.

---

## 2. NDC — GPU가 쓰는 좌표

정점 셰이더가 `SV_Position`으로 내놓아야 하는 것은 **NDC(Normalized Device Coordinates)**다.

```
            +1  ┌─────────────┐
                │             │
                │             │
             0  │      ·      │  ← (0, 0)이 화면 정중앙
                │             │
                │             │
            -1  └─────────────┘
               -1      0     +1
```

| | 범위 | 방향 |
|---|---|---|
| x | -1 (왼쪽) ~ +1 (오른쪽) | 오른쪽이 + |
| y | -1 (아래) ~ +1 (**위**) | **위가 +** |
| z | 0 (가까움) ~ 1 (멂) | D3D 기준. OpenGL은 -1~1 |

**y가 위로 +인 것이 함정이다.** 화면 픽셀 좌표와 UV 좌표는 둘 다 **아래가 +**다.
이 셋이 섞이는 지점에서 "그림이 위아래로 뒤집혔다"가 나온다.

```
NDC             화면 픽셀          UV
 y↑              (0,0)            (0,0)
  │                ┌────→ x        ┌────→ u
  └────→ x         │               │
                   ↓ y             ↓ v
 위가 +           아래가 +         아래가 +
```

## 3. 왜 하필 -1 ~ 1인가

**해상도와 무관하게 만들기 위해서다.**

같은 장면을 1280×720에도 3840×2160에도 그려야 한다.
좌표가 픽셀이면 셰이더가 해상도를 알아야 하고, 해상도가 바뀔 때마다 값이 전부 바뀐다.

-1~1로 정규화해 두면 셰이더는 해상도를 몰라도 된다.
**실제 픽셀 변환은 뷰포트가 마지막에 한다.**

```cpp
D3D11_VIEWPORT viewport{};
viewport.Width  = 1280;   // NDC -1~1을 이 폭에 펼친다
viewport.Height = 720;
```

창 크기가 바뀔 때 `CreateBackBufferView()`에서 뷰포트를 다시 설정하는 이유가 이것이다.
안 하면 새 창 크기와 안 맞아 그림이 잘리거나 남는다.

---

## 4. 화면 좌표 → NDC 변환

핵심 수식이다. 유도를 따라가 두면 외울 필요가 없다.

**x부터.** 화면 x는 `0 ~ width`, NDC x는 `-1 ~ +1`이다.

```
1) 0~width  를 0~1 로       :  x / width
2) 0~1      를 0~2 로       :  x / width * 2
3) 0~2      를 -1~1 로      :  x / width * 2 - 1
```

```hlsl
ndc.x = (screenX / screenWidth) * 2.0 - 1.0;
```

**y는 방향이 반대라 마지막에 부호를 뒤집는다.**

```hlsl
ndc.y = 1.0 - (screenY / screenHeight) * 2.0;
```

검산해 보자.

| 화면 좌표 (1280×720) | NDC | 맞나 |
|---|---|---|
| (0, 0) 좌상단 | (-1, +1) | ✓ |
| (640, 360) 중앙 | (0, 0) | ✓ |
| (1280, 720) 우하단 | (+1, -1) | ✓ |

## 5. 크기는 어떻게 되나

**위치는 이동(offset)이 있지만 크기는 없다.** 크기는 배율만 곱한다.

```hlsl
ndcWidth  = (pixelWidth  / screenWidth ) * 2.0;
ndcHeight = (pixelHeight / screenHeight) * 2.0;
```

200픽셀 폭은 1280 화면에서 `200/1280*2 = 0.3125`다.
`-1` 을 빼지 않는 것에 주의. 그건 원점을 옮기는 항이라 길이에는 해당이 없다.

---

## 6. 코드로는 — 어디서 변환할까

두 가지 방법이 있고, 3장에서 **B를 쓴다.**

**A. C++에서 미리 변환해 정점 버퍼에 NDC로 넣기**
- 셰이더가 단순해진다
- 스프라이트가 움직일 때마다 정점 버퍼를 다시 써야 한다

**B. 픽셀 좌표를 그대로 넘기고 셰이더에서 변환** ← 이쪽
- 화면 크기를 상수 버퍼로 셰이더에 알려준다
- 위치가 바뀌어도 정점 버퍼는 그대로. 상수 버퍼만 갱신
- 나중에 인스턴싱으로 갈 때도 자연스럽다

```hlsl
cbuffer ScreenInfo : register(b0)
{
    float2 screenSize;   // (1280, 720)
    float2 padding;
};

float2 ScreenToNDC(float2 screenPos)
{
    float2 ndc = screenPos / screenSize * 2.0 - 1.0;
    ndc.y = -ndc.y;      // y 뒤집기
    return ndc;
}
```

> **3D에서는 어떻게 되나 (맛보기)**
> 3D는 이 변환이 행렬 곱으로 바뀔 뿐 목적지는 같다.
> `로컬 → (월드 행렬) → 월드 → (뷰 행렬) → 카메라 기준 → (투영 행렬) → 클립 공간`
> 이고, 마지막에 GPU가 `w`로 나누면(원근 나눗셈) NDC가 나온다.
> **어떤 3D 파이프라인이든 마지막은 NDC다.** 지금 배우는 게 그 끝단이다.
>
> 지금 `float4(pos, 0.0f, 1.0f)`에서 w에 1을 넣는 것이 "원근 나눗셈을 하지 않겠다"는 뜻이다.
> 1로 나누면 그대로니까. 2D라서 그렇게 둔 것이다.

---

## 7. 종횡비 문제

NDC는 x도 y도 -1~1이지만 **화면은 정사각형이 아니다.**

1280×720 화면에서 `0.5 × 0.5` 크기 사각형을 그리면 **가로로 늘어난 직사각형**이 나온다.
NDC 0.5가 x로는 320픽셀, y로는 180픽셀이기 때문이다.

픽셀 단위로 크기를 지정하면(6번의 B 방식) 이 문제가 자동으로 사라진다.
화면 크기로 나누는 과정에 종횡비가 이미 들어 있다.

> **엔진에서는** — 카메라의 Aspect Ratio가 이 보정을 한다.
> 창 크기를 바꿨는데 화면이 늘어나 보이는 버그는 대개 이 값을 갱신 안 한 것이다.

---

## 8. 흔한 함정

**y를 안 뒤집음**
→ 그림이 위아래로 뒤집힌다. 텍스처가 붙은 뒤에야 알아채는 경우가 많다.
삼각형은 대칭이라 안 보였을 수 있다.

**뷰포트를 갱신 안 함**
→ 창 크기를 바꾸면 그림이 잘리거나 한쪽에 몰린다.

**크기 변환에 `-1`을 넣음**
→ 위치 수식을 그대로 복사하면 이 실수가 난다. 크기는 배율만이다.

**픽셀 좌표를 그대로 정점에 넣음**
→ `(640, 360)`은 NDC로 치면 화면 밖 한참 바깥이다. 아무것도 안 보인다.

**정수 나눗셈**
→ C++에서 `200 / 1280`은 **0**이다. `200.0f / 1280.0f`로 써야 한다.
HLSL은 float가 기본이라 이 문제가 없지만, C++ 쪽에서 미리 계산할 때 걸린다.

## 9. 확인 문제

1. 1920×1080 화면에서 화면 좌표 (960, 270)은 NDC로 얼마인가?
2. 왜 y만 부호를 뒤집는가?
3. NDC가 픽셀이 아니라 -1~1인 이유를 한 문장으로.
4. 1280×720에서 NDC 크기 `0.5 × 0.5`인 사각형은 실제로 몇 픽셀 × 몇 픽셀인가? 정사각형인가?
5. 위치 변환에는 `- 1.0`이 있는데 크기 변환에는 없다. 왜인가?

> 1번 답 — x: `960/1920*2-1 = 0`, y: `1 - 270/1080*2 = 0.5`. 즉 `(0, 0.5)`.
> 화면 가로 중앙, 세로로는 위쪽 1/4 지점. NDC에서 위가 +이므로 0.5가 맞다.
>
> 4번 답 — x는 `0.5/2*1280 = 320`픽셀, y는 `0.5/2*720 = 180`픽셀.
> **정사각형이 아니다.** 7번의 종횡비 문제가 이것이다.

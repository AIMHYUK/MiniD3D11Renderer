# 강의 구조와 지금 구조 비교

> 상태: 진행중 · 갱신 2026-08-11 · 관련: [1단계 작업일지](../작업일지/2026-08-11_1단계_창과_D3D11_초기화.md)
> 무엇: 홍정모 그래픽스 강의 실습(`Desktop/HGraphics/01_DX11InitAndImGui`)과 이 프로젝트의 1단계 코드가 무엇이 같고 무엇이 왜 다른가.

---

## 먼저 — D3D11 호출 순서는 거의 같다

"많이 다른가"에 대한 답부터. **다르지 않다.** Direct3D를 쓰는 순서 자체는 정해져 있어서
누가 짜도 같은 모양이 나온다.

```
초기화
  WNDCLASSEX 등록 → AdjustWindowRect → CreateWindow → ShowWindow
  디바이스 + 스왑체인 생성
  swapChain->GetBuffer(0)        // 백버퍼 텍스처 꺼내기
  CreateRenderTargetView         // "여기에 그린다" 뷰
  RSSetViewports                 // 뷰포트

매 프레임
  OMSetRenderTargets → ClearRenderTargetView → (드로우) → Present
```

강의 코드도 이 순서고 지금 코드도 이 순서다. `AdjustWindowRect`로 클라이언트 크기를
보정하는 것도, `PeekMessage` 루프를 쓰는 것도 똑같다.

**다른 건 이 호출들을 어디에 두느냐, 그리고 뒷정리를 누가 하느냐다.**

---

## 다른 점 여섯 가지

| | 강의 (`Example.h`) | 지금 |
|---|---|---|
| 파일 구성 | 헤더 하나에 319줄 전부 인라인 | `Window` / `Renderer` / `main` 분리 |
| COM 해제 | 원시 포인터 + `Clean()`에서 수동 `Release()` 14줄 | `ComPtr`이 스코프 끝에서 자동 |
| 에러 처리 | `std::cout << "... error"` 찍고 계속 진행 | `HR_CHECK`가 파일·줄·HRESULT 의미까지 표시하고 중단 |
| 스왑체인 | `D3D11CreateDeviceAndSwapChain` + BitBlt 모델 | 디바이스/스왑체인 분리 + Flip 모델 |
| 창 크기 변경 | `case WM_SIZE:` 비어 있음 (주석만) | `ResizeBuffers`까지 구현 |
| 서브시스템 | 콘솔 (`int main`) — `cout`으로 디버깅 | 윈도우 (`wWinMain`) |

### 1. 헤더 하나 vs 파일 분리

강의가 헤더 하나에 몰아넣은 건 **강의라서**다. 화면에 코드를 띄우고 위에서 아래로
읽어 내려가야 하는데, 파일이 넷이면 왔다 갔다 해야 한다. 학습에는 이쪽이 낫다.

제출물은 반대다. 네오플 제출 요건이 *"아키텍처, 핵심 로직 및 코드 구조가 상세히
기술된 설명"*이다. 319줄짜리 클래스 하나는 설명할 아키텍처가 없다.

### 2. `ComPtr` vs 수동 `Release()`

강의의 `Clean()`은 이렇게 생겼다.

```cpp
if (layout)        { layout->Release();        layout = NULL; }
if (vertexShader)  { vertexShader->Release();  vertexShader = NULL; }
// ... 14줄 반복
```

**낯설어 보이지만 원리는 간단하다.** D3D11 인터페이스는 전부 COM 객체고, COM은
참조 카운트로 수명을 관리한다. `Release()`가 카운트를 하나 줄이고, 0이 되면 실제로 없어진다.

`ComPtr`은 그 `Release()`를 소멸자에서 대신 불러주는 스마트 포인터다. `std::unique_ptr`이
`delete`를 대신 불러주는 것과 같은 관계다.

```cpp
ComPtr<ID3D11Device> m_device;   // 스코프를 벗어나면 알아서 Release
```

그래서 `Clean()` 자체가 없다. **강의가 손으로 하는 것을 컴파일러에 맡긴 것뿐이고,
하는 일은 완전히 같다.** 어느 쪽이 어렵고 쉬운 게 아니라, 빠뜨릴 수 있느냐 없느냐가 다르다.

> 면접에서 "ComPtr이 뭔가요"를 물으면 이렇게 답하면 된다 —
> COM 참조 카운트를 RAII로 감싼 것. `AddRef`/`Release`를 복사·소멸에 맞춰 자동으로 부른다.

### 3. 에러 처리

강의는 실패해도 `cout`에 찍고 계속 간다. 콘솔 창이 떠 있으니 눈으로 보라는 뜻이다.
초기화가 실패하면 그다음 줄에서 어차피 널 포인터로 죽는데, 그게 학습에는 문제가 안 된다.

지금은 어디서 왜 실패했는지 메시지 박스로 알리고 멈춘다.

```
D3D11CreateDevice 실패
HRESULT : 0x887A0004
내용    : The specified device interface or feature level is not supported...
위치    : C:\...\Renderer.cpp(74)
```

이게 더 좋아서라기보다, **창 서브시스템이라 콘솔이 없기 때문**이다. `cout`을 쓸 데가 없다.

### 4. 스왑체인 — 여기가 진짜 차이

강의는 `DXGI_SWAP_EFFECT_DISCARD`(BitBlt 모델)를 쓴다.
지금은 `DXGI_SWAP_EFFECT_FLIP_DISCARD`(플립 모델)다.

BitBlt 모델은 Present 때마다 백버퍼를 화면 버퍼로 **복사**하고, 플립 모델은 **포인터를 바꿔 끼운다.**
자세한 건 → [스왑체인과 플립 모델](스왑체인과_플립모델.md)

강의가 옛 방식을 쓰는 건 `D3D11CreateDeviceAndSwapChain` 한 방으로 끝나서다.
그 함수는 플립 모델을 만들 수 없어서, 플립을 쓰려면 팩토리를 손으로 구해야 한다.
줄 수는 늘지만 매 프레임 화면 크기만큼의 복사가 사라진다.

### 5. `WM_SIZE`가 비어 있다

```cpp
case WM_SIZE:
    // Reset and resize swapchain
    return 0;
```

강의 코드는 주석만 있고 구현이 없다. 창 크기를 바꾸면 그림이 늘어난다.
강의 진도에서 아직 안 다룬 것이지 틀린 게 아니다.

## 강의 구조로 바꿀 것인가

**권하지 않는다. 이유가 둘이다.**

### 하나 — 그 구조는 강사의 것이다

`Example` 클래스 이름, `canvasWidth`/`canvasHeight`, `Update()`에서 픽셀 배열을 채워
`Map`/`memcpy`/`Unmap`하는 흐름은 그 강의의 특징적인 설계다.
제출물에 그대로 옮기면 "본인이 설계한 아키텍처"라고 말하기 어렵다.

호출 순서가 같은 건 문제가 없다. D3D11 API가 그 순서를 요구하니까.
**클래스 구성과 이름을 옮기는 것이 문제다.**

### 둘 — 목적이 다르다

강의의 캔버스 구조를 보자. `1280/80 = 16`, `960/80 = 12` — **16×12짜리 아주 작은 텍스처**를
만들고, CPU에서 픽셀 배열을 채운 다음, 화면 전체를 덮는 사각형 하나에 입혀 확대한다.
샘플러 필터도 `MIN_MAG_MIP_POINT`(뭉개지 않고 네모나게 확대)다.

**이건 GPU 렌더링을 가르치는 구조가 아니라, CPU에서 계산한 픽셀을 화면에 띄우는 발판이다.**
그 강의가 레이트레이싱으로 가기 때문이다.

이 프로젝트는 반대 방향이다. 스프라이트를 **여러 개** 그리면서 드로우 콜 수에 따라
성능이 어떻게 갈라지는지를 본다. 드로우 콜이 언제나 하나인 구조로는 그 실험을 못 한다.

---

## 그래도 가져올 것

- **desc 구조체를 필드별로 한 줄씩 채우고 주석 다는 방식.** 무엇을 설정하는지 눈에 보인다.
  지금 코드도 이미 그렇게 하고 있다.
- **`Update()`와 `Render()`를 나눈 것.** 상태 갱신과 그리기를 섞지 않는다.
  4단계에서 스프라이트 위치를 움직이게 되면 지금 `Render()` 하나를 이 둘로 쪼갤 것.
- **ImGui.** 스프라이트 개수를 슬라이더로 바꿔가며 FPS를 보면 실험이 훨씬 빠르다.
  5단계에서 붙일지 검토. (다만 외부 라이브러리가 하나 생긴다)

## 정리

| 궁금한 것 | 답 |
|---|---|
| 많이 다른가? | D3D11 호출 순서는 거의 같다. 감싸는 방식이 다르다. |
| 뭐가 더 어려운가? | 어느 쪽도 아니다. `ComPtr`은 `Clean()` 14줄을 없앤 것뿐이다. |
| 강의 스타일로 바꿀까? | 아니다. 클래스 구성이 강사 설계고, 캔버스 구조로는 배칭 실험을 못 한다. |
| 그럼 어떻게 익히나? | 2단계부터 직접 친다. 순서는 정해져 있으니 외울 게 많지 않다. |

# 공부 로드맵 — 무엇을 왜 공부하는가

> 상태: 진행중 · 갱신 2026-08-11 · 관련: [작업일지 목차](_목차.md), [기초 — 창과 D3D11의 등장인물](개념/00_기초_창과_D3D11의_등장인물.md), [7일 커리큘럼](7일_커리큘럼.md)
> 무엇: 게임사가 DirectX를 요구하는 진짜 이유와, 그에 맞춰 무엇을 어느 순서로 공부할지의 우선순위.

---

## 그들이 원하는 것은 API 암기가 아니다

공고에 쓰인 단어를 그대로 보자.

- 스마일게이트 6098 — "3D그래픽스 및 DirectX **기본 지식** 보유자"
- 네오플 — "DirectX를 활용한 2D/3D 게임 프로그래밍 및 **응용 능력**"

C++에는 "숙련자"라고 썼으면서 DirectX에는 그렇게 쓰지 않았다. 의도적인 차이다.

## 그럼 무엇을 보는가

네오플 업무 내용이 답을 준다.

> "유저 환경 최적화를 위한 **메모리/렌더링 최적화** 및 클라이언트 안정성 강화"
> "**DX11 엔진 기능 개선**, 내부 툴 개발, 신기술 연구"
> "기존 **대규모 레거시 소스 코드 분석(리딩)** 능력과 빠르고 정확한 디버깅 능력"

전부 **이미 있는 코드를 읽고 고치는 일**이다. 새로 짜는 일이 아니다.

버그는 이런 모양으로 들어온다.

| 증상 | 의심할 곳 |
|---|---|
| 캐릭터가 반투명하게 겹쳐 보임 | 블렌드 상태 / 그리는 순서 / 뎁스 테스트 |
| 특정 맵에서만 프레임 드랍 | 드로우 콜 수 / 텍스처 메모리 / 오버드로우 |
| 입력이 한 프레임 늦게 반응 | 스왑체인 버퍼 개수 / Present 큐잉 |

**이걸 좁히려면 "프레임 하나가 어떻게 만들어지는가"의 그림이 있어야 한다.**
그림이 있으면 함수 이름은 5초면 검색한다. 그림이 없으면 검색어조차 못 떠올린다.

## 언리얼만 해서는 이 그림이 안 생긴다

언리얼은 이걸 전부 대신 해준다. 메시 컴포넌트를 붙이면 그려진다.
편한 대신 문제가 생겼을 때 안이 안 보인다.

한 번 손으로 해보면 그다음부터 엔진 안이 보인다. **이 프로젝트의 진짜 목적이 그것이다.**
렌더러를 잘 만드는 게 아니라, 엔진이 대신 해주던 일을 한 번 겪는 것.

## 우선순위

### A급 — 반드시. 면접에서 나온다

**1. 렌더링 파이프라인 단계 — `IA → VS → RS → PS → OM`**
각 단계가 무엇을 받아 무엇을 내놓는가. **전부의 뼈대다.** 이거 하나면 나머지가 다 걸린다.

**2. 좌표계 변환**
로컬 → 월드 → 뷰 → 투영 → 스크린. 왜 행렬을 곱하는가. 원근이 어디서 생기는가.
(이 프로젝트는 2D라 스크린 ↔ NDC 변환까지만 다룬다)

**3. 드로우 콜이 왜 비싼가**
CPU가 GPU에 명령을 제출하는 비용, 상태 변경 비용, 드라이버 오버헤드.
배칭과 인스턴싱이 왜 필요한가. → 4~6일차가 정확히 이것.

**4. CPU와 GPU는 따로 논다**
`Draw()`는 명령을 큐에 넣을 뿐, 그 순간 그려진 게 아니다.
그래서 GPU 시간을 재려면 타임스탬프 쿼리가 필요하다.
성능 문제가 CPU 탓인지 GPU 탓인지 가르는 근거가 여기서 나온다. → 7일차.

### B급 — 알면 크게 유리

5. 뎁스 버퍼와 Z-fighting
6. 알파 블렌딩과 그리는 순서 — 투명은 왜 뒤에서 앞으로 정렬해야 하는가
7. 텍스처 — UV, 밉맵, 필터링, BC 압축, 메모리 차지
8. 상태 객체(블렌드·뎁스스텐실·래스터라이저)를 왜 미리 만들어 두는가

### C급 — 나중에

셰이더 최적화, 디퍼드 렌더링, 포스트 프로세싱, 컴퓨트 셰이더

## 외울 필요 없는 것

- `D3D11_SWAP_CHAIN_DESC1` 같은 desc 구조체의 필드 이름 → 문서 보고 채운다
- 함수 인자 순서 → IntelliSense가 알려준다
- HRESULT 값 → 검색한다

1단계 초기화 코드 100줄도 외워서 쓴 것이 아니다. 문서를 보고 쓴 것이다. 그게 정상이다.

## 면접에서 나오는 형태

- "드로우 콜을 줄이는 방법은?"
- "투명 오브젝트는 왜 따로 그리나요?"
- "프레임 드랍이 났을 때 CPU 바운드인지 GPU 바운드인지 어떻게 판단하죠?"
- **"포트폴리오에서 배칭 실험을 하셨는데, 왜 하필 그 개수부터 차이가 났나요?"**

마지막이 제일 많이 나온다. **본인이 만든 것에 대한 질문**이기 때문이다.
그래서 실측 숫자와 "왜 그 지점인가"에 대한 본인 해석이 있으면 강하다.
MiniOscReceiver에서 이미 한 방식 그대로다.

## 이 프로젝트가 A급을 전부 덮는다

| 단계 | 몸으로 익히는 것 |
|---|---|
| 2단계 정점·셰이더 | **A급 1** — IA/VS/PS가 실제로 무엇을 주고받는지 |
| 3단계 텍스처·상수버퍼 | **A급 2**, B급 7 |
| 4단계 블렌딩 | B급 6, 8 |
| 5~6단계 배칭 비교 | **A급 3** — 드로우 콜 비용을 숫자로 |
| 7단계 계측 | **A급 4** — CPU/GPU 비동기 |
